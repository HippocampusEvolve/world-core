# world-core

Общее ядро миров [find-the-end.fun](https://find-the-end.fun). Здесь живёт то,
что у всех миров одинаково и что не знает ни про один из них: контроллер от
первого лица и процедурные материалы. Сюжета в ядре нет и не будет - он
остаётся в приватном репозитории витрины.

| Часть | Состояние |
|---|---|
| [`src/materials`](src/materials) - процедурные карты и материалы | готово |
| [`src/props`](src/props) - предметы каталога: геометрия из примитивов, поверхность из наборов | каталог и процедурная лопата |
| [`src/core`](src/core) - тело, взгляд, ввод, риг инструмента, руки | ходит в Snowfall и Winter Tower |

## Новые поверхности и лопата

Десять нейтральных рецептов `surfaceSnow`, `surfaceRock`, `surfaceGravel`,
`surfaceConcrete`, `surfaceWood`, `surfaceRust`, `surfaceMetal`,
`surfaceCloth`, `surfaceIce`, `surfacePaper` дополняют прежние 19 наборов.
Размер 256², normal из высоты, повторение по обеим осям. Мир задаёт цвет;
`SURFACE_MEAN_LINEAR[name]` позволяет компенсировать яркость карты перед
клонированием материала. `bake()` возвращает массивы и работает в Worker.

`shovel({ wood, steel })` из `world-core/props` строит лопату высотой 1,45 м:
остриё в начале координат, черенок вдоль +Y, вогнутая сторона к -Z.
Два меша, материалы передаёт мир, риг и анимация остаются у вызывающей стороны.

## Материалы

Третий путь к предмету, между «слепить в Blender» и «набрать голой геометрией
кодом»: геометрия из примитивов, а поверхность считается кодом. Ни одного файла
текстур в сборке - только генераторы.

```js
import { makeSet, material, boxUV } from 'world-core/materials'

const set = makeSet('rubble')                       // посчитать карты один раз
const mat = material(set, { normalScale: 1.2 })     // материал из них
const g = new THREE.BoxGeometry(w, h, d)
boxUV(g, w, h, d, 0.5)                              // UV в метрах: 1 тайл на 2 м
```

Девятнадцать наборов: брёвна сруба, бутовый камень (холодный и тёплый), тёсаная
кладка (тёплая и холодная), плиты очага, кирпич топки (с сажей и без), половая
доска, тёсаный брус, кора, торцы поленьев, ткань, чугун, шерстяной плед,
плетёный коврик, кожа переплёта, обрез страниц, колотое дерево.

Последние пять пришли вместе с мебелью хижины (28.08.2026). У каждого своя
причина быть отдельным набором, а не подкраской ткани: плед в клетку, потому
что одноцветный прямоугольник на кровати читается крышкой ящика; кожа
переплёта светлая и почти серая, потому что цвет корешку даёт подкраска, и
одна карта обслуживает всю полку; коврик радиальный, как торец полена, и
кладётся на круг целиком; раскол полена светлее коры в полтора раза, и это
утверждение проверки, а не пожелание.

Бут и тёсаная кладка - разные породы кладки, а не два вкуса одной. Бут это
валуны клеточным шумом, границы органические; тёсаная кладка - обтёсанный камень
рядами с перевязкой, сколотыми кромками и узким швом. Её числа сняты с
референса, а не выбраны на глаз (замер и что он поймал - в комментарии
генератора).

Набор карт считается ОДИН раз и раздаётся многим поверхностям: `material()`
клонирует текстуры ради своего числа повторов, и это ничего не стоит - three
держит объект видеокарты в кэше по `source` плюс параметры сэмплера, а `repeat`
и `offset` в ключ кэша не входят. Кэш наборов по имени - `cachedSet(name)`:
предмет каталога берёт набор по имени, и мир не должен знать, кто ещё его
просил.

### UV в метрах: две ручки, которых не хватало мебели

`boxUV(geo, w, h, d, s, along)` - ось коробки, вдоль которой идёт волокно. У
всех деревянных наборов волокно лежит по V, а штатная развёртка кладёт V на
боковые грани вверх: у царги кровати или столешницы волокно вставало поперёк
доски, и глаз читал это мгновенно. С `along` грань, у которой названная ось
идёт по U, разворачивается на четверть; торцы остаются как есть.

`discUV(geo, radius)` - круг целиком на одну карту, для радиальных наборов с
серединой. Крышки цилиндра у `cylinderUV` развёрнуты в метрах, и для плит
очага на срезе пня это верно; для торца полена - нет: при радиусе в пять
сантиметров на торце оказывалась четверть карты вокруг её угла, то есть кора
и изнанка вместо колец. Поленья в топке Snowfall так и стояли, пока их не
пересчитали заново для поленницы.

### Устройство

```
noise.ts       периодический шум: hash2, vnoise, fbm, ridge, worley
shape.ts       мелочь для цвета: smoothstep, mix, add
bake.ts        выпечка карт БЕЗ DOM - отсюда числа берёт проверка
generators.ts  сами материалы и рецепты (размер, рельеф, тайлинг)
textures.ts    единственное место, где есть three и канва
uv.ts          UV в метрах: boxUV, planeUV, cylinderUV, quadGeometry
```

Разрез между `bake.ts` и `textures.ts` - не косметика. Правило проекта:
геометрию и материал проверяем счётом, браузером последним. Оно выполнимо
только когда карты считаются там же, где считается проверка: на Node, без окна.

### Проверка

    npm run check

Считает все девятнадцать наборов и проверяет 107 утверждений. Меряется три вещи.

**Шов на стыке тайла - точно, без порога.** Генератор это функция от `u = x/S`,
и карта стыкуется сама с собой ровно тогда, когда функция периодична:
`f(1) = f(0)`. Значит её можно просто вычислить при `u = 1`, за краем карты, и
сравнить с `u = 0`. Совпало - шва нет, и это тождество, а не оценка. Меряются
обе карты, которые из функции растут: цвет и высота (разрыв в высоте невидим в
цвете, но карта нормалей строится из неё, и на стыке идёт полоса чужого
освещения).

**Рельеф.** Средний наклон нормали в градусах: ловит материал, приехавший
плоским при зелёных остальных числах.

**Утверждения.** У каждого генератора в комментарии написано словами, каким он
должен получиться («раствор темнее камня», «в камне металла нет вовсе»). Те же
слова записаны неравенством и проверяются вместе с картой.

Порог под материал не подкручивается. Набор, которому стыковаться незачем,
объявляется таким в рецепте - поимённо и с причиной; таких два, и оба видно в
отчёте.

**Замер, подогнанный под материал, ничего не мерит.** Утверждение «кладка идёт
рядами» переписывалось трижды, и первые два раза виноват был прибор. Поиск
локальных минимумов насчитал 66 провалов при четырёх рядах - зерно камня даёт
свои, а отделяет их только сглаживание, шаг которого и становится порогом.
Спектр выглядел строже, но шов это узкий импульс, а у него гармоники 4, 8, 12,
16 равны по высоте: замер показывал то вторую, то шестнадцатую при исправной
кладке. Работает третий вариант, самый прямой: в каждой доле карты самая
непохожая на медиану строка обязана стоять на разделе рядов. Усреднять не по
чему - значит и подбирать нечего.

Зато первый же честный замер нашёл в материале настоящий дефект: сильнее рядов
читалась полосатость, потому что в ряду 3-5 блоков и средняя яркость ряда гуляла
сама по себе. Лечится тем, что тон блока отсчитывается от среднего по своему
ряду.

Девятнадцать плиток, на каждой набор уложен 3 на 3: стыки видно только там,

## Предметы

    import { bed, table, stool, rug, shelfWithBooks, logStack } from 'world-core/props'

    const b = bed({ w: 1.02, l: 2.1 })
    b.group.position.set(x, floorY, z)
    scene.add(b.group)

Предмет - функция с параметрами, возвращающая группу three и свои габариты.
Геометрия из примитивов, поверхность из наборов ядра, про мир предмет не
знает ничего: мир ставит группу, заводит коллайдер по габаритам и при
желании подменяет материалы по ролям (`mats`) - Snowfall так кладёт снежный
налёт на кору поленницы. Это и есть каталог, о котором шла речь: «поставь
здесь коврик, там кровать» не требует от мира ни строчки про материалы, а
предмет, отлаженный в одном мире, переезжает в другой как есть.

Шесть предметов: кровать (каркас на ножках, изголовье, матрас, плед с полами,
подушка), стол с царгами и табурет на трёх ногах, круглый плетёный коврик,
полка на кронштейнах с рядом книг и кружкой, стопка колотых поленьев - и
само колотое полено как геометрия (`splitLogGeometry`): сектор цилиндра с
корой по дуге, торцами и плоскостями раскола, группы по ролям.

**Детали стоят друг на друге, а не друг в друге.** У кровати плед лежит на
матрасе, полы свисают снаружи каркаса с зазором в миллиметр, царги стола идут
между ногами встык, а не сквозь них. Это не аккуратность ради аккуратности:
геометрия предметов проверяется счётом (`world-check-kit`, `npm run audit --
props` в витрине) на копланарные грани одной стороны и тела друг в друге,
и проверка зелёная потому, что предметы под неё собраны, а не потому, что ей
что-то разрешили.

**Наклонённая книга** стоит нижним углом на полке, а верхним касается
соседки: наклон вокруг центра коробки утопил бы угол в доску на семь
миллиметров, и проверка тел назвала бы это первым.

**Поленья лежат кто корой кверху, кто расколом.** Стопка одной корой кверху
в кадре была тёмным бугром без единой светлой плоскости. Высота ряда при
этом честная: верх любого полена ряда - на радиус выше пола ряда, будь то
макушка коры или плоскость раскола, и следующий ряд ложится на оба одинаково.

**Геометрия без канвы.** Наборы ядра пекутся на канве, которой у Node нет, а
проверке нужны треугольники. `blankMats()` подставляет пустые материалы, и
предмет собирается на Node той же функцией, что в игре, - копий геометрии
для проверки не существует.

### Казённые предметы

Сорок предметов обихода: крашеное железо, эмаль, фанера, брезент. У них
общий уклад, и он строже, чем у мебели хижины.

    import { locker, coat, coatBoard } from 'world-core/props'

    const l = locker({ sealed: true, mats: { paint: wallGreen } })
    const b = coatBoard()
    const c = coat({ reach: b.hooks[0].z, seed: 2 })
    c.group.position.copy(b.hooks[0])
    b.group.add(c.group)

**Роли материалов - из закрытого словаря** (`ROLES` в `roles.ts`). Предмет
называет, из чего сделана деталь, одним словом, мир подменяет роль своим
материалом через `mats`, и одна подмена перекрашивает всю комнату: шкафчик,
койка и щит берут один `paint`. У каждой роли есть набор ядра по умолчанию -
для мира, который ничего не подменил; `roleMats(mats, tint)` отдаёт материал
роли с кэшем, `tint` - свой цвет предмета по умолчанию (огнетушитель
красный).

| Роль | Что | Набор по умолчанию |
|---|---|---|
| `paint`, `paint2` | крашеный металл или дерево; вторая краска - кант, крест, ручка | `surfaceRust` |
| `steel`, `brass` | голый металл | `surfaceMetal` |
| `rust` | ржавчина | `surfaceRust` |
| `wood` | дерево | `surfaceWood` |
| `cloth` | ткань, брезент, матрас | `surfaceCloth` |
| `rubber` | резина, шланг, кабель | `leather` |
| `glass`, `water` | прозрачное, глубину не пишет | `surfaceIce` |
| `enamel` | эмаль | `surfaceMetal` без металличности |
| `paper`, `photo` | бумага; плоскость снимка с UV от 0 до 1 | `surfacePaper` |
| `plastic` | пластмасса, карболит | `surfaceConcrete` |
| `soil`, `leaf`, `fruit` | земля, листья, плоды | `surfaceGravel`, `surfaceCloth`, `surfacePaper` |
| `tube`, `bulb`, `screen`, `dial`, `led`, `shade` | светится: трубка, лампочка, экран, шкала, огонёк, абажур | `surfacePaper`, `surfaceCloth` с эмиссией |

Роли вне словаря нет: мир не узнал бы, что ей подменить. Проверка
(`npm run audit -- props` в витрине) ловит и её, и роль без набора.

**Начало координат.** Стоящий на полу - середина пятна на полу, лицо к +Z.
Настенный - на плоскости стены: z = 0 - грань стены, предмет выступает в +Z,
x = 0 - середина; где начало по высоте, сказано у предмета (раковина - от
пола, аптечка - середина корпуса). Висящий плащ - точка подвеса. Габариты
`w`, `d`, `h` - рамка собранного предмета по X, Z, Y; рабочие высоты
(столешница, край чаши, лежак) и полезные точки (крючки, места табличек,
конец излива) - отдельными полями.

**Подвижные части** - подгруппы с опорой на оси и `userData`: `moving`
(имя: `door`, `door-left`, `drawer`, `lid`, `hands-minute`...), `motion`
(`rotate` или `slide`), `axis` (локальная ось), `sign` (куда открывается),
`limit` (угол или ход). Мир крутит или двигает подгруппу вокруг её начала;
содержимое ящика кладётся в саму подгруппу (`userData.inside` - дно).

| Файл | Предметы |
|---|---|
| `furniture.ts` | `bench`, `chair`, `chairStack` (стулья вставлены друг в друга), `desk` (тумба с ящиками), `nightstand`, `sideboard` (дверцы), `workbench` (тиски, молоток, ключ), `crate` (крышка) |
| `storage.ts` | `locker` (`open` - пустые плечики, `sealed` - бумажная пломба), `medCabinet` (крест `paint2`, пузырьки), `panelBox` (автоматы), `jerrycan` (`full`), `bucket` (вода вровень с краем) |
| `fixtures.ts` | `coatBoard` (`hooks`, `labels`), `coveredMirror` (простыня отдельным мешем), `extinguisher`, `cableTray` (кабели на прутках), `washbasin` (`rim`, `spout`), `wallClock` (три стрелки), `photoFrame`, `nightLamp` |
| `cloth.ts` | `coat` (`hood`, `cape` - плащ-палатка, `width`, `reach`), `boots` |
| `beds.ts` | `bunk` (голые доски, `levels`), `cot` (застелена), `rolledMattress`, `foldedCot` |
| `lab.ts` | `plantRack` (лампа-планка над полкой), `tomatoPlant` (`seed`), `jar`, `microscope`, `tagBox`, `scales` (гиря едет), `bandage`, `scissors` |
| `tableware.ts` | `mug` (`fill`), `sugarBowl` (крышка отдельно), `cupShelf` (чашки `cup-1`...`cup-N` отдельными мешами) |
| `stationery.ts` | `openBook` (блоки страниц `pages`), `pen` |

Надписей, цифр и табличек на предметах нет: их кладёт мир - на плоскость
с UV от 0 до 1 (циферблат, снимок) или в точку, которую предмет вернул.

**Формы сверх коробки и цилиндра** (`shapes.ts`): труба по ломаной с усами
на стыках (`pipe`), тело вращения по профилю из прогонов со своими
материалами (`revolve`), тело по сечениям с плоской спиной и сдвигом вершин
(`loft`), полотно с толщиной (`slab`), выдавленный контур (`extrude`),
скругление углов ломаной (`fillet`). Все они замкнуты и смотрят гранями
наружу: проверка тел считает внутренность чётностью луча, а у незамкнутой
поверхности чётность случайна. Корпус из щитов с дверцами, ящиками и
полками - `carcass` (`cabinet.ts`): на нём стоят стол, тумбочка, сервант,
шкафчик, аптечка и щит.

**Тонкое на тонком - самая частая претензия.** Две грани одной стороны
ближе сантиметра друг к другу спорят за глубину, и тонкая пластина с чем-то
на ней даёт такую пару почти всегда: низ блока страниц в трёх миллиметрах
над низом обложки, верх ленты под матрасом, верх планки под дном лотка.
Лечится устройством, а не допуском: обложка журнала - рамка вокруг блоков,
а не доска под ними; под матрасом и лотком круглые прутки с нечётным числом
граней, у них сверху и снизу ребро, а не грань; жалюзи шкафчика наклонены.

**Опора - тоже сосед.** Проверка ставит под каждый предмет пол или стену, и
так нашлись снимок в 4 мм от стены, планка кронштейна в 8 мм и дно ящичка в
8 мм над столом: сами по себе чистые, в мире они полосили бы. Правило то же:
лицо тоньше сантиметра от опоры - только если площадью оно меньше
квадратного дециметра.

**Плащ - одно тело.** Рукав, пришитый отдельной трубой, уходил плечом в
корпус на пять сантиметров. Рукава, складки и неровный подол - сдвиг вершин
того же тела по сечениям, и тел в плаще одно (плюс петля). На доске 1.3 м
крючки идут через 0.275, а плащ по рукавам 0.53: соседние плащи зашли бы
друг в друга, поэтому в тесном ряду `width` - шаг крючков, а лишнее как бы
спрятано за соседом.

## Контроллер

Тело, взгляд, ввод, риг инструмента и сцена рук. Взято из Snowfall - там у
контроллера уже есть тач, coyote-прыжок, сглаживание ступенек, раскачка обзора,
защита вида у стены и аналоговый ввод.

Правило разреза одно: **ядро владеет всем, что про тело и намерение игрока, мир
владеет всем, что про геометрию.** В типах ядра нет ни вокселя, ни капсулы, ни
octree, ни рельефа: форма мира входит через один интерфейс из трёх методов.

### Что должен дать мир

```ts
interface Support {
  // Пол под точкой в окне высот [yFrom − probe, yFrom]. yFrom уже поднят на
  // шаг вверх, то есть это же число - потолок досягаемости шагом. Имя
  // поверхности выбирает мир: тело им не пользуется, а передаёт в шаги и
  // приземление.
  floorAt(x, z, yFrom, probe): { y: number; surface: string } | null

  // Вытолкнуть тело из твёрдого. Правит pos на месте; тело - вертикальная
  // капсула, круг радиуса radius на отрезке высот [pos.y, pos.y + height].
  // Скорость трогать не обязательно: ядро само отнимет ту её часть, что
  // смотрит в поверхность, по суммарному смещению за кадр.
  resolve(pos, radius, height, vel, dt): void

  // Необязательный. Знаковое расстояние от глаза до ближайшей поверхности
  // (в воздухе положительное) и единичная нормаль наружу. По нему ядро держит
  // near-плоскость камеры снаружи стены; null - миру нечего прятать.
  clearance?(eye): { dist: number; normal: Vector3 } | null
}
```

Сверх этого мир даёт спавн, колбэки шага и приземления и свои числа: темп
ходьбы и бега, прыжок, гравитацию, высоту глаза, радиус, шаг вверх и вниз,
coyote, выносливость. Все они - опции с умолчаниями, и умолчание у каждого
своё, не общее «разумное»: это походка Snowfall, снятая с рабочей игры.

### Что даёт ядро

`SmoothLook` - взгляд с телом: сглаживание, крены в вираж и на стрейфе, клевок
приземления, микронаклон разгона, дыхание в покое, `?rawlook`, `lock()/unlock()`.
`Input` - клавиатура, мышь и палец в одном намерении `Intent { move, run, jump,
action, tool }`; тело читает только его и про документ не знает ничего. Сюда же
входит `TouchControls`: кнопки он создаёт сам, но их id, иконки и подписи
приходят от мира - раскладку в кадре им даёт CSS страницы.
`Body` - намерение в скорость, гравитация, прыжок и coyote, выносливость,
сглаживание ступенек, качка, шаги по дистанции, приземление, защита вида.
`HeldTool` - риг замахов с кейфреймами, hitstop и отдачей камеры; сами
инструменты (их позы и что делать при контакте) остаются в мире.
`ViewModel` - сцена рук со своим FOV и своим depth; свет и окружение
инъекцией.

### Подключение

```js
import { Body, Input, SmoothLook, ViewModel } from 'world-core/core'

const look = new SmoothLook(camera, canvas)
const input = new Input({ look, target: canvas, onAction, onTool })
const player = new Body({ camera, input, support, spawn, onStep, onLand })
const view = new ViewModel(camera, { keyDir: sunDir })

function frame(dt) {
  look.update(dt, player) // взгляд РАНЬШЕ тела: движение идёт по свежей камере
  player.update(dt)
  view.update(dt, player)
}
```

### Проверка

`test/core.test.mjs` гоняет тело на Node с плоской заглушкой `Support`: путь за
три секунды ходьбы, высота и возврат прыжка, coyote в окне и за окном, срок
бега при заданном расходе выносливости. Браузера там нет вовсе - именно ради
этого намерение ставится присваиванием в `Input`, а не синтетической клавишей.

## Что нашлось при переносе

Эталон писался как одностраничная демонстрация и на r128. При переезде в
библиотеку на текущий three нашлись вещи, которых в нём не было видно.

### Карты не стыковались сами с собой

Главное. У всего шума в `noise.ts` есть период решётки, и карта тайлится ровно
тогда, когда множитель координаты совпадает с периодом и оба целые:
`fbm(u * 5, v * 5, 5, 5, ...)` - да, `fbm(u * 5, v * 1.4, 5, 1, ...)` - нет.
В эталоне почти каждый второй вызов был вторым видом. То же с синусами (`|sin|`
имеет период π, поэтому целым должно быть удвоенное число оборотов) и с
индексами ячеек: `hash2(Math.floor(u * 4), ...)` на самом краю даёт доску 4
вместо доски 0.

Прыжок цвета на стыке тайла, из 255:

| набор | было u | было v | стало |
|---|---|---|---|
| брёвна сруба | 37 | 182 | 0 |
| бутовый камень | 0 | 184 | 0 |
| плиты очага | 173 | 173 | 0 |
| кирпич топки | 22 | 42 | 0 / объявлено |
| половая доска | 116 | 25 | 0 |
| тёсаный брус | 0 | 32 | 0 |
| кора дров | 0 | 62 | 0 |
| ткань | 38 | 56 | 0 |

В хижине это не читалось: при свете очага полоса на четырёхметровой стене
выглядит ещё одним пятном копоти. Ловится только счётом.

Правки, изменившие картинку, все здесь: у бревна свиль `v*1.4 → v*1`, волокно
`3.4 → 3.5` оборота, трещины `v*2.4 → v*2`, сучки `v*2.6 → v*3`; у бута камни
`v*3.2 → v*3`; у плит очага `3.4 → 3` по обеим осям; у кирпича рядов `9 → 8`
(нечётное число ломает перевязку на стыке) и индекс столбца через `wrapi`; у
доски коробление `v*1.6 → v*2` и индекс доски через `wrapi`; у бруса
коробление `v*1.2 → v*1`, волокно `3.2 → 3`; у коры хребты `v*2.2 → v*2`; у
ткани переплетение задано числом нитей на тайл вместо шага в пикселях.

### Сажа кверху - это ручка, а не свойство кирпича

У кирпича топки сажа густела к верху карты монотонным градиентом. Для топки
высотой в один тайл это верно, но такая карта не стыкуется по вертикали в
принципе: у монотонного градиента верх с низом не сходится по определению.
Градиент стал параметром: `firebrick(1)` - как в эталоне, `firebrick(0)` -
тайлится в обе стороны. Оба варианта в рецептах, оба под проверкой.

### Замер шва врал, пока был статистическим

Первый заход мерил резкость кромки относительно медианного перепада между
соседними столбцами. Он давал 2-4 «раза» у кирпича и половой доски при
совершенно исправной периодичности - потому что у кладки кромка тайла попадает
ровно на шов раствора, на линию резкую ПО ЗАМЫСЛУ, а медиана считается по сотням
гладких столбцов внутри камня.

Замер заменён на точный (`f(1)` против `f(0)`), и чтобы новый не оказался просто
мягче старого, в проверке ему подсовывают ровно ту ошибку, которая была в
эталоне: индекс доски без заворота. Не поймает - грош ему цена.

### Мерить уклон одного материала бессмысленно

Проверка «кирпич без градиента ровный по высоте» сравнивала среднюю яркость
верхней четверти с нижней и требовала разницы меньше 5%. Получила 13% и была
неправа: в верхней четверти карты всего восемь кирпичей, у каждого свой
случайный тон, и десяток процентов набегает раскладкой. У кирпича С сажей та же
раскладка даёт +13%, у кирпича БЕЗ сажи −13%, и по отдельности оба числа
выглядят одинаково подозрительно.

Случайность у них при этом одна и та же, поэтому спрашивать надо не «ровный
ли», а «что делает ручка»: разницу уклонов, в которой раскладка сокращается. А
что кирпич без градиента и правда ровный, доказывает не эта проверка, а нулевой
шов: у монотонного градиента он нулевым быть не может.

### Цветовое пространство: старая строчка не падает, а молчит

Эталон писал `texture.encoding = THREE.sRGBEncoding`. Этого свойства больше нет:
с r152 цветом заведует `texture.colorSpace`, а константа убрана совсем. Ловушка
в том, что старая строчка не роняет сборку - она заводит на объекте лишнее поле,
которое никто не читает. Базовый цвет уезжает в линейное пространство, картинка
выцветает, и это списывают на тонмаппинг.

Правило: КАРТИНКА - в sRGB, ДАННЫЕ - без цветового пространства. Нормаль,
шероховатость и металл это числа, любая гамма их портит. В `textures.ts` им
проставлен `NoColorSpace` явно, чтобы это было видно глазами, а не держалось на
значении по умолчанию.

### `envMapIntensity = 0` нельзя переносить в библиотеку

В эталоне у каждого материала стоял жёсткий ноль, и стоял правильно: окружения
там не было вовсе. В библиотеке этот ноль молча погасил бы отражения любому
миру, у которого окружение есть, причём симптом выглядел бы как «материал
слишком матовый», а причина лежала бы за три файла. Здесь свойство не трогается,
пока его не попросят.

### Металл без окружения - чёрная дыра, и это арифметика

У металла нет рассеянной составляющей: его базовый цвет это цвет отражения. У
чугуна он 42 из 255, то есть в линейных единицах около 2%. Умножьте на тусклое
небо - получите байт двенадцать, то есть чёрный квадрат. В хижине чугун читался
потому, что рядом горел огонь и на решётке стоял блик, а не потому, что материал
был другим. Вывод для миров: карта металла без карты окружения не работает
(см. бэклог витрины).

### Канва, а не DataTexture

`DataTexture` избавила бы от канвы совсем, но у неё `flipY = false`, а весь
эталон построен на том, что канва переворачивается: у генераторов `v = 0` это
ВЕРХ поверхности. Поднять `flipY` у `DataTexture` мешает неоднозначность в самом
WebGL - `UNPACK_FLIP_Y_WEBGL` надёжно работает для картинок и канвы, а для
сырого буфера ведёт себя по-разному. Проверять это в каждом браузере дороже, чем
оставить канву.

## Подключение

### Калиброванные поверхности

`surfaceSnow` использует профиль снега Snowfall и разрешение 1024².
`surfaceTowerSnow`, `surfaceTowerRock`, `surfaceTowerGravel` и остальные
`surfaceTower*` используют отдельные профили Winter Tower. Дерево, ткань и
ржавчина имеют 512², остальные 1024². Яркость, контраст, полосы частот,
roughness и сила normal подогнаны к исходным картам. Пиксели файлов в библиотеку
не входят: поля создаются хешем и спектральным синтезом, normal выводится из
высоты с необязательным измеренным сдвигом средней нормали.

`SURFACE_MEAN_LINEAR` соответствует разрешению рецепта. Карты башни без
исходного diffuse имеют белый albedo и не требуют цветовой карты в материале.
Синтез запускайте в Worker: карты 1024² дороже 256² и по времени, и по GPU-памяти.
Временные поля освобождаются через необязательный `Generator.release` после
`bake`. `Generator.normalBias` задаёт постоянный наклон в касательном пространстве.

Репозиторий публичный, поэтому игры берут его прямо из git:

```json
"dependencies": {
  "world-core": "github:HippocampusEvolve/world-core"
}
```

Собранный `dist/` лежит в репозитории намеренно: `npm install` у чужого
человека, склонировавшего публичную игру, не должен требовать ни компилятора, ни
сети сверх самого клона. Отсюда правило: **правка в `src/` не считается
сделанной, пока не прогнан `npm run build`** - иначе игры получат вчерашний код.

`three` идёт peer-зависимостью (`>=0.170`): версию выбирает мир, а не ядро.

## Живые миры: `world-core/ecology`

Процедурные лиса, олень и ворон (`createAnimal`), ограниченная популяция с
проверкой рельефа (`createWildlife`), семь видов растений (`plantGeometry`,
`createVegetation`) и пространственные голоса природы (`createNatureSoundscape`).
Животные занимают 560–1220 треугольников, растения — до 5000 на вариант;
растения объединены в пространственные InstancedMesh. Материалы используют
цвета вершин, без загружаемых моделей и текстур. Звук подключается к существующей
шине мира и ограничен пятью одновременными голосами.

Передавайте `active: false` при паузе, реальный рельеф и препятствия в `Habitat`,
а настройку уменьшенного движения — в `reducedMotion`. Ресурсы освобождаются
методом `dispose()`. Источники визуальных референсов и границы их использования:
[src/ecology/PROVENANCE.md](src/ecology/PROVENANCE.md).

`npm run check` проверяет воспроизводимость геометрии, бюджет треугольников,
проходимость, независимость движения от частоты кадров и пределы аудиосигналов.
